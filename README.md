# АгроМаркет API

## Запуск
1. Установить PostgreSQL, создать базу agromarket
2. Скопировать .env.example в .env и указать свой пароль
3. npm install
4. npm run db:init   # создать таблицы и загрузить товары
5. npm run dev       # http://localhost:3000

## Эндпоинты
| Метод | Путь | Описание | Ответы |
|---|---|---|---|
| GET | /api/health | сервер и связь с БД | 200 |
| GET | /api/products | товары, ?search= | 200 |
| GET | /api/products/:id | один товар | 200, 400, 404 |
| POST | /api/products | создать товар | 201, 400 |
| PUT | /api/products/:id | изменить товар | 200, 400, 404 |
| DELETE | /api/products/:id | удалить товар | 204, 404 |
| GET | /api/orders | заявки + название товара | 200 |
| POST | /api/orders | новая заявка | 201, 400 |
| PATCH | /api/orders/:id | сменить статус заявки | 200, 400, 404 |

Тесты: коллекция postman/agromarket.postman_collection.json (11 запросов, 13 проверок, 0 failed; повторный запуск тоже зелёный).

## Лабораторная 6 — ответы
- **Ошибки из части 2:**
  - `price = -5` → `violates check constraint "products_price_check"` (сработал `CHECK (price >= 0)`);
  - без `name` → `null value in column "name" ... violates not-null constraint` (`NOT NULL`);
  - `product_id = 9999` → `violates foreign key constraint "orders_product_id_fkey"`, `Key (product_id)=(9999) is not present in table "products"` (внешний ключ).
  Через API: 23514 / 23502 / 23503 → errorHandler → 400 с понятным текстом; для `product_id: 9999` ответ сформировал errorHandler (код 23503, «Связанная запись не найдена»), а не маршрут.
- **SQL-инъекция:** с вклеиванием `${search}` запрос `?search=zzz' OR 1=1 --` вернул **все** товары, хотя «zzz» нет ни в одном названии; одна кавычка `'` → синтаксическая ошибка SQL → **500**, в терминале стек ошибки. После возврата к `$1` оба запроса дают **200** и пустой массив `[]`: значение передаётся как данные, а не как часть SQL.
- **Двойная защита quantity:** без JS-проверки `quantity: 5` всё равно не сохраняется: база отклоняет строку по `CHECK (quantity >= 10)` (код 23514), errorHandler отвечает 400 «Значение не проходит проверку в БД». JS-проверка нужна, чтобы вернуть пользователю понятное сообщение («Минимальный объём заказа — 10 кг»), не тратя запрос к базе; CHECK — последняя линия защиты на случай, если в код попадёт другой путь записи или проверку забудут.
- **Что стало с заявкой после удаления товара:** заявка осталась, `product_id` стал `NULL` (`ON DELETE SET NULL`), в `/api/orders` у неё `product_name: null` (благодаря LEFT JOIN заявка не пропала из выдачи).
